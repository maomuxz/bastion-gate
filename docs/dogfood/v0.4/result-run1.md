# v0.4 自举第一轮结果（2026-11-18）

## 结论
bastion v0.3 + 手工空架子，用 `bastion run` 把 v0.4 的 6 块全部建完：6 次 AI 调用，全部一次通过，0 返工，用时 4.9 分钟。
合并后全量测试 39/39 通过（复检 3 遍），审计无篡改，改动只落在每块被允许的文件里。

## 用量（只统计 bastion 施工 AI，不含设计/出题）
见 [usage-run1.md](usage-run1.md)。要点：
- 合计约 114 万 token，其中 92% 是缓存读（便宜，约正常输入价的一成）；按 API 价折算约 0.59 美元。
- N4（就绪队列，改 400 行的 run.ts）一块占 42%，15 轮；其余 5 块各占 8%–14%，5–8 轮。
- **每次调用有固定底座**：哪怕 N1 只改一行，也读了约 8 万缓存。原因是每一轮都要重读系统提示 + 工具定义 + 已读文件。开销 ≈ 轮数 × 上下文大小。

## 为什么这次 0 返工（对比 早先的私有项目 第二批 17 块只有 1 块一次过）
1. 接口在空架子里先锁死，施工 AI 只填函数体。
2. 每块只准改指定文件，互不打架。
3. 验收是能跑的测试，并且把本块的测试命令直接写进提示。
4. 任务小而清楚。——这一条也是警告：这轮的块偏简单，不能直接外推到大项目。

## 没算进去的大头
空架子、6 份测试、施工计划都是小克（Opus）在对话里做的，这部分 token 没有被 usage.jsonl 记录，很可能比施工本身还多。
下一步要让 planner / tester 也走 roles 槽位、同样记账，才算得出完整账单。

## 哪里可以压
1. **轮数**：AI 每跑一次测试就读回一大段输出；我们的测试会把内层 bastion 的日志全打出来，噪音很大。让测试安静（内层 console 静音）能直接减少每轮的上下文。
2. **返工反馈**：失败时给 AI 的 40 行里约七成是调用栈。这轮没返工所以没花钱，返工多时值得只留断言部分。
3. **固定底座**：施工 AI 已隔离掉用户级设置、MCP、技能；剩下的是 Claude Code 自身的系统提示，压不了，只能靠少轮数。
