## 3. 补哪些、不补哪些（全部保持不绑 Harness、不强求多模型）

### 3.1 补进通用 CLI 的功能

1. **项目地图 + 白纸重做对比 + 接口桩生成（`bastion map`）**
   - 命令形态：`bastion map "<需求>" [--spec <file>] [--planner "<cmd>"] [--recheck "<cmd>"]`
   - 读写文件：读需求文本与仓库目录 → 调两次独立干净的 Planner 会话（默认复用 `agentCommand`，也支持配不同模型 CLI）分别输出 `.bastion/plan.json` 与 `.bastion/plan.recheck.json` → 程序对比节点与依赖差异写出 `.bastion/map-diff.md`，同时生成 `.bastion/interfaces.md`（接口锁定约定）与 `.bastion/acceptance.md`（白话验收句）。

2. **白话回译与出场确认（`bastion review`）**
   - 命令形态：`bastion review [--approve]`
   - 读写文件：读 `.bastion/plan.json`、`.bastion/acceptance.md`、`.bastion/map-diff.md` → 生成一页白话报告 `.bastion/brief.md`（做出来什么样、分几波、有几处分歧与高风险三档）；用户 `--approve` 后写入 `.bastion/approvals.json`。

3. **三档授权账本 + 攒批提问（`bastion ask` / `bastion decisions`）**
   - 命令形态：`bastion ask`（逐条批复三档问题）、`bastion decisions`（扫一眼二档自动决定账本）
   - 读写文件：`.bastion/decisions.json`（二档按推荐执行后的记录，含理由与可回滚提示）、`.bastion/inbox.json`（节点遇到三档卡点时写入待拍板队列，不阻塞其他无依赖并发节点；本批可跑的跑完后统一等 `bastion ask` 拍板，再 `bastion run --resume`）。

4. **分岗槽位与“出题 → 施工 → 质检”三阶段闭环（升级 `config.json` 与 `bastion run`）**
   - 命令形态：`bastion run [--with-tests] [--with-qa]`（保持兼容现有 `run`）
   - 读写文件：`.bastion/config.json` 新增可选 `roles: { plannerCommand?, testerCommand?, workerCommand?, qaCommand? }`（缺省全部回退到 `agentCommand`，单模型干净会话即可跑，有条件也可换不同模型）；执行流升级为 `tester` 出红测试并自动 `lock` → `worker` 并发施工 → `gate` 硬门禁 → `qa` 按验收句核验（输出 `.bastion/qa/<nodeId>.json`，程序硬拦“测试失败算推迟”）。

5. **预算闸（Budget Gate）**
   - 配置写入 `.bastion/config.json`：`budget: { maxAgentCalls?, maxMinutes?, maxCostUsd? }`，运行进度记入 `.bastion/run-state.json`。每次派发前检查余额，触顶优雅暂停并提示“加预算后 `--resume`”。

6. **机器级轻量编译槽位锁（可选）**
   - 参数：`bastion run --global-slots <n>`，读写 `~/.bastion/slots/`，防止同时跑多个仓库时把本机 CPU/内存打满。

### 3.2 不补进通用 CLI、只写进文档或留给项目自定义配置的

- **早先的私有项目 专属规则**：Flutter/Dart 专属 `早先的私有项目-run.sh` 环境注入、WPS 成品验收与夜跑脚本、UI 组件库 tokens 一致性检查、题库准确性格式化器等——全部属于特定业务栈，写进文档作为 `extraChecks` / `setupCommand` 接入示例，不写死进 Bastion。
- **重型性能组**：各语言性能基准差异极大，v1.0 前不做内置压测框架，仅支持用户将自己的压测脚本挂入 `testCommand` 或 `extraChecks`。

## 5. 最大的风险与防“做一半就宣传”的铁律

- **最大风险**：
  1. **被拆得太重，失去通用性**：`map` / `tester` / `qa` 一旦依赖 AI CLI 输出格式，容易因为各家 CLI 升级或提示词波动变得脆弱，且多轮调用会显著增加 token 消耗（《流水线设计》第三批曾消耗约 2500 万 token）。
  2. **功能刚搭出骨架就在外部没跑过真项目的情况下急着宣传**，导致口碑透支。
- **硬防线**：
  1. **结构化输入输出全靠文件契约**：AI 只负责把 JSON/Markdown 写进 `.bastion/` 约定路径，格式校验和状态流转全由确定性程序完成（写错格式直接退回重填）。
  2. **没有真实中型靶子全链路录屏，禁止发宣传视频**：每个版本发布后，必须在一个 8～10 模块的独立真项目上（包含白纸对比找分歧、三档攒批、预算闸、多波次并发、3 遍全绿）用真模型从头跑通一次，拿到真实耗时/拦截数/token 账单后，再拍宣传视频。

## 6. 以后视频应该讲什么

- **一句话定位**：  
  > **“给 AI 编程造一座棱堡：先用双份地图对齐需求、锁死考卷，再放手让多个 AI 并发干活，人只在关键节点拍板。”**
- **故事主线**：  
  - 痛点不再只讲“AI 偷改测试”，而是放大成 AI 编程的**双重困境**：**盯着它干活累死人，撒手不管它就漏需求、偷改测试、越改越乱**。
  - 破局思路：**城外筑墙（先红锁测试 + 硬门禁，防作弊）** + **城里流水线（一句话拆地图 + 独立重做抓盲区 + 多工作区并发 + 三档攒批等人拍板）**——你只管在开头审一页白话、中间批一次高风险决定、最后收三遍全绿的成品，中间全由这座城防自动跑完。
