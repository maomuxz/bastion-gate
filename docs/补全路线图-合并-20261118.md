# Bastion 补全为完整棱堡 · 合并路线图（小克 × 小安，2026-11-18）

依据：`早先一个私有项目的流水线/docs/流水线设计.md`（原设计）、`bastion-开源交接.md`、v0.3.0 代码。
两份独立方案：`补全方案-小安-20261118.md`、小克方案（会话内）。本文为合并结论。

## 最终定位（mmxz 11-18 定）

bastion = **确定性护栏**（借鉴 Lauren Tan / Grok Bot 团队演讲里的工程理念：规则写成程序，人只看验证结果）**+ 多 agent 并发**（对齐 Antigravity /swarm 一类的做法：多个 AI 各自隔离同时开发）**+ 两者都没管的那块**（两份地图对比保证"拆对了"、先红后锁、三档授权让人不在也不卡）。
- 对外说"借鉴 / 对齐"，不说"就是他们的框架"，不暗示有关联或背书。
- /swarm 具体做法目前多为二手报道，宣传前须找一手来源核对。
- 一句话草稿：**让一群 AI 同时开发，同时保证它们没偷懒、没作弊、没跑偏，大事才来找你。**

## 事实
- v0.3.0 的 plan/run 调度是 mmxz 11-17 选"路线 B（完整棱堡）"后加的；交接文档"调度一律不碰"与他本意不符。
- v0.3.0 已有：先红后锁、基线硬门禁、变异抽查、audit、DAG 波次 + worktree 并发 + 门禁打回重试 + 合后 N 遍复检、plan.json 的 tier/approved（第三档未批不跑）。
- 缺：需求→地图、白纸重做对比、白话回译、二档决定账本、三档攒批、"你不在时"、预算闸、出题/施工/质检分岗、接口先锁/递归、出场 4 次闭环。

## 原则（两人一致）
1. 不绑 harness、不强求多模型：每个岗位是 config 里的一条命令，缺省都回退 `agentCommand`。
2. AI 只往 `.bastion/` 约定文件里写 JSON/Markdown，格式校验与状态流转全由程序做，写错退回重填。
3. 早先的私有项目 专属（WPS、一致性覆盖、早先的私有项目-run.sh、重型性能组）不进 CLI，只写文档 + `extraChecks` 接入示例。

## 风险
- token 成本：原流水线三批约 2500 万子 agent token；map/qa 多轮调用要配预算闸和默认小规模。
- 各家 AI CLI 输出格式波动：靠文件契约 + 程序校验兜住。

## 行业风向（调研见 `调研-AI测试与回滚-小安-20261118.md`，小克核对后更正）

- 来源：Lauren Tan（poteto，"土豆姐"，SpaceXSI / Grok Bot 团队，前 Cursor）在 AI Engineer CODE（2026-11 中旬）的演讲《All Code Is Slop (Except Mine)》。核心：别把规则堆在 AGENTS.md 里，把重复犯错写成**确定性护栏**（架构边界 → 静态分析/类型/测试/CI → 运行时验证 → 最后才是人审）；人只看验证结果，不逐行读 AI 代码。
- 数字只能说"约"：团队约 1.1 万 PR/月、回滚率约 0.5%，**团队自报、相对口径**。小安报告里的 10,926 / 0.47% 未在原始来源核到，不用。
- 判断：bastion 的"程序硬拦、不靠 AI 自觉"正踩在这个方向上；"先红后锁 + 基线防改 + 双份地图 + 三档攒批"的组合未查到同类开源。
- **调整**：v0.4 加 `checks`（静态分析/架构规则命令，gate 先跑再跑锁定测试，工作量小，对齐护栏前几层）；v1.0 增强 `audit`：合入后回归挂了，定位是哪次 bastion 合并引入，给出 `git revert` 建议（只管代码，不做线上自动回滚）。
- 宣传红线：只能说"行业在往确定性门禁走"，**不能**说用了 bastion 就能到 0.5% 回滚率，也不说"自动线上回滚"。

## 预算：钱花在哪、怎么省（小克，2026-11-18 补）

**只有"调用 AI"花钱。** 跑测试、gate、合后复检、mutate、audit 都是普通程序，不花 token。
bastion run 的花费 ≈ 节点数 × 每节点尝试次数 × 每次会话读进去的上下文量。

**实测（早先的私有项目 流水线，原设计文档 §6 表）：** 到第三批约 2500 万子 agent token——画地图 ~310 万（23 个助手）、第一批 ~520 万、**第二批 ~1260 万（最贵）**、第三批 ~450 万+。
第二批贵在**返工**：门禁变严后一次过只有 1/17，103 个助手里大量是返工和修复。

**三个大头：** ① 返工（一次过率低）；② 每块固定 3 个岗位（出题 Opus + 施工 Sonnet + 质检 Opus）；③ 每次会话都通读大仓库（Flutter 项目上下文很大）。

**回滚花不花钱：** 代码回滚本身免费——失败的节点在自己的 worktree/分支里，不合并就等于回滚，主分支从来不被碰。但失败那一轮已经花掉的 token 收不回来，返工又是新的一轮。所以省钱的关键是**少失败**，不是回滚。

**办法（按效果排）：**
1. **提一次过率**：出题提示写进已踩过的坑（BOM、记录里套 List 别用 == 比、导出按字节比）；"测试有误"走单独通道，不让施工白干。
2. **先便宜后升级**：施工先用便宜模型，失败才换强模型重做。
3. **缩上下文**：每次只给本节点相关文件 + 接口约定 + 上一轮报错，不通读仓库；返工只发 diff 和报错。
4. **按活大小分档**：小活跳过白纸重做和多轮质检（原设计五条补丁之二）。
5. **预算闸**（v0.4）：每批上限，触顶停到第三档等人加预算。
6. 能用程序就不用模型（已在做）。

## 自举（dogfooding）：用手动模拟的棱堡流程做 bastion v0.4

在 v0.4 功能写出来之前，**先由人和 AI 手动扮演棱堡的各个岗位**，用这套流程来开发 bastion 自己：
1. **出场①复述确认**：小克用白话复述 v0.4 范围，mmxz 确认。
2. **地图**：小克（设计师）画 v0.4 节点图（roles 槽位、decisions 账本、ask/inbox、status --away、预算闸）+ 依赖 + 接口 + 验收句；**小安当白纸重做者**（Gemini，正好是异家模型）只看需求独立画一份；对比分歧逐条裁决。
3. **出场②白话回译**：一页白话给 mmxz 认验收句。
4. **出题**：每个节点先写会失败的测试，**用 bastion 自己的 `bastion lock` 锁住**。
5. **施工**：每节点一个 worktree，尽量用 `bastion run --agent "claude -p ..."` 真跑（自己的调度器做自己）。
6. **门禁**：`bastion gate` + `mutate`，合进集成分支，复检 3 遍。
7. **三档手动记账**：二档决定写 `docs/dogfood/decisions.md`，三档（如发 npm）停下问 mmxz——等于先用文件模拟 v0.4 要做的功能。
8. **记每一步花的 token**：用实测数字回答"预算到底多少"。
