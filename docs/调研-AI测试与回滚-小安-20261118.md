## 1. 事实核查：“Grok Bot 土豆姐”与那场演讲

- **人物是谁**：**Lauren Tan**，网名 **`@poteto`**（谐音 potato，中文社区称“土豆姐”），前 React 核心团队成员，xAI / Grok Bot 团队工程负责人（Principal Engineer / software lead）。
- **哪场分享**：**2026 年 11 月**（具体日期待进一步核对日程表，为近期刚结束的 **AI Engineer** 峰会）发表演讲 **《All Code Is Slop (Except Mine)》**。
- **核心数据与观点**：
  1. **极高吞吐 + 极低回滚率**：公开了 Grok Bot 团队 10 月的生产数据——团队单月合入 **10,926 个 PR**（她个人 10 月合入 **3,127 个 PR**），桌面端保持约每天一版的发布节奏，而 **10 月 Commit 回滚率仅 0.47%**。
  2. **“Poteto 信任倒金字塔”与“软件花园（Software Garden）”**：
     - 面对 AI 生成大量垃圾代码、人类Review不堪重负的痛点，她反对把越来越多规则塞进 Markdown 提示词（`AGENTS.md`），主张把重复犯错变成**确定性的代码级护栏**（Codebase 架构边界 → Static Analysis/Lint/类型/单元测试/CI → Verification 运行时/不变式验证 → 最底层的 Human Review）。
     - 人工审查退化为**只看验证产物与测试报告**，不再逐行读 AI 代码。

## 2. 2025～2026 年业界“AI 测试”与“降回滚”代表动向

业内正在发生一个共识反转：**“写代码已经变便宜了，验证和安全才是昂贵瓶颈”**。围绕“把关前移（Left-Shift）”和“上线后自动止损（Right-Shift）”，2025～2026 年代表性的产品与研究包括：

1. **Meta ACH（Automated Compliance Hardening，2025 年初发表）**：
   - 将**变异测试（Mutation Testing）与 LLM 结合**：先用 LLM 根据自然语言风险描述生成“能编译且能绕过现有测试的真实故障变异体”，再生成专门杀死这些变异的单元测试（在 Messenger/WhatsApp 等内测中约 73% 生成测试被工程师采纳）。
   - 来源：[Meta Engineering / arXiv 论文《Mutation-Guided LLM-based Test Generation at Meta》](https://vertexaisearch.cloud.google.com/grounding-api-redirect/AUZIYQF42DF2yLgUi6xIRk1q4-8num5FjtDBgj-lMRS_v_uZw6U7S1isbdBlGSdFkdXgl4GeNgfC9yzlaJztG_B_XRDIEgfep9s8EBSZrpkxTThhQlvkwS44Yg==)（2025）
2. **Qodo（原 CodiumAI，2025～2026）**：
   - 聚焦 PR 阶段的“信任税（Trust Tax）”与上下文感知测试生成、多仓库规则审查与代码质量治理，解决 AI 写代码后评审卡顿的问题。
   - 来源：[Qodo 官网](https://vertexaisearch.cloud.google.com/grounding-api-redirect/AUZIYQFpPMpSWc2yzaf0qL9tWEkDDnzEXnv29Z3YaWTxD_FhZlNNe4681Kl8tQG2pZNPqtD-YtkmFk157KTJNjBZd_S5ZWnDDDgnGqbhCvscdEiJePiqHdlIV66-jIW1nC00o7X41PMHGhBpSx1B) / [VMblog 2026 报告报道](https://vertexaisearch.cloud.google.com/grounding-api-redirect/AUZIYQGPLjNwtryH6bvn8KRgdo3DVr7dtl5iLwp_wqDlFCKsImmaqVhUua1ba-UhRuFUtEDv9kNPmJRSqsjLntAa27nb1PjsJ8ZTwAecHbCbdP6jZ_PSYBjPgXXJAff3anIajWSX6dyy13IXZOhhz7omSi-5Y-mEfVtz6NQnWKxXDVaHt8tw5Gu5vNN9_0813CyNxL-XmbDf7XvVuKOvQoRxvf2icyowxGqq6Fd0HWvLEPzQcrCZZcvk2taFJ2R-ICHumg==)

## 3. 与 Bastion 的对比：已有 / 缺失 / 独有，以及“回滚”怎么看

| 维度 | 行业主流做法 | Bastion 现状 | 判断 |
|---|---|---|---|
| **把重复犯错变成确定性硬护栏（非只写 `AGENTS.md`）** | 土豆姐演讲核心思想 | **已有**（`gate` 从基线读规则、`lock` 防假红、程序强制检查） | 理念完全踩中行业最前沿 |
| **隔离并发与合前复检** | Grok Build / Worktree 隔离 | **已有**（`worktree` + `bastion/run-*` 集成分支 + N 遍复检） | 已有且干净 |
| **变异测试** | Meta ACH（LLM 语义变异+自动补测试） | **部分有**（`mutate` 做了固定规则轻量抽样，缺 LLM 语义变异与自动补测试） | 方向一致，可按需演进 |
| **静态分析与架构边界约束** | 土豆姐金字塔第 1～2 层（自定义 Lint/禁用危险 API） | **部分有**（可通过 `extraChecks` 挂载，但 `init` 没内置引导） | 行业强、我们较薄 |
| **合入后自动回滚（Right-Shift）** | Harness 等基于生产监控秒级回滚 | **没有** | 见下方专项分析 |
| **先红后锁 + 基线防篡改 + 双份地图对比 + 三档攒批** | 行业多关注“AI 写得快”或“上线监控” | **Bastion 独有组合** | 非常稀缺的差异化护城河 |

### 专项分析：Bastion 需不需要做“合并后发现问题自动回滚”？

- **不建议做“生产环境运行时自动回滚”**（那是 Harness / Argo Rollouts / LaunchDarkly 等 CD 平台的事，需要接 APM 监控和部署系统，做了会彻底偏离代码仓库 CLI 的轻量边界）。
- **但非常值得做一个轻量的“Git 合入前/合入后本地防线”**：
  1. **合入后降回滚（Shift-Left 降低 `revert` 率）**：土豆姐说的“0.47% 回滚率”，核心恰恰是**靠合入前的硬门禁和确定性验证把坏代码挡在 `main` 外面**——这正是 Bastion 现在做的事（`bastion/run-*` 集成分支隔离 + 3 遍全绿才准人合入 `main`，本身就把 `main` 的回滚率往 0 压）。
  2. **可选加一个小命令 `bastion verify-merge`（或增强 `audit`）**：合入 `main` 后如果后续 CI/本地全量回归挂了，能一键定位是哪次 `bastion/*` 合并引入的、并生成安全的 `git revert -m 1 <merge_sha>` 建议（只针对代码合并，不碰生产数据）。

## 4. 对 Bastion 路线图与借势宣传的建议

### 4.1 路线图优先级调整建议（借上“高吞吐 + 低回滚”风口）

1. **v0.4.0（最贴合“降回滚”主线，建议优先）**：
   - 保持“分岗槽位 + 三档账本/攒批 + 预算闸”为核心；
   - **顺手加一项高性价比升级**：在 `config.json` 增加 **`checks`（静态分析/架构规则命令数组，如 `tsc --noEmit` / `eslint`）**，在 `gate` 里先跑静态分析再跑锁定测试——直接对齐土豆姐倒金字塔的前三层（静态分析 + 测试验证），开发量极小（小工作量）却让产品叙事完整很多。
2. **v0.5.0（对齐“人工不逐行看 Slop 代码，只看验收清单与产物”）**：
   - `bastion map` + `bastion review`：用双份地图对比 + 一页白话回译，让人类彻底摆脱“逐行审 AI 垃圾代码（Review Bottleneck）”的痛苦，只审白话验收要点与测试结果。
3. **v1.0.0（跑出真实“低回滚率”战报）**：
   - 找一个 8～10 模块的中型项目真跑一轮，统计出 **“并发合入 PR/节点数、拦截作弊次数、合入后 `main` 回滚率”**（哪怕是小样本，只要数据真实），再对齐行业热点发布。

### 4.2 怎么借势宣传（不夸大、不蹭歪）

- **怎么借势（推荐说法）**：
  - 引用土豆姐演讲公开数据作行业背景：**“AI 编程已经进入‘写代码很便宜、验证和防回滚才最贵’的阶段（连 Grok Bot 团队能做到单月上万 PR、0.47% 回滚率，靠的也是把规则写成确定性门禁，而不是靠 AI 自觉）。”**
  - 然后自然切入 Bastion：**“但不是每个团队都有大厂自研的内部底座——Bastion 就是给个人和小团队用的开源‘确定性门禁 + 并发流水线’：先红后锁防假测试、基线门禁防改测试、独立 worktree 并发过关再汇入主线。”**
- **绝对不能说的话（防反噬）**：
  - ❌ 不要宣称“用了 Bastion 就能做到 0.47% 回滚率 / 像 Grok Bot 一样每天发版”（那是人家整套基础设施和工程文化的结果，不能往自己身上揽）；
  - ❌ 不要吹“自动线上回滚”（Bastion 管的是合并前的测试锁与并发隔离，不是线上 APM 监控回滚）。
