## 三、已知问题和没做的事

1. **变异测试**：加了超时（超时算被抓到并标注）。上一次的结果里有两条是死循环被手动结束的，不算数；
   带超时的重跑结果见本文末尾"变异测试"一节（写这份文档时还在跑）。
2. **开关没有逐个实测**。方案里的规矩是"默认打开必须有实测依据"，现在只有村庄档跑过真模型；
   城邦、王都两套预设只有假角色的自动测试。
3. **搭空架子的开关**：关掉它而仓库里又没有现成接口文件时，测试只能因导入失败而红，锁会拒绝，流程停在上锁。
   这是施工方提异议后确认的，开关只适合已有接口文件的仓库。
4. **补题后不重新挑漏**。现在只由程序检查"原有用例一条不少、至少新增一条、别的测试文件没动"，
   不保证新增的用例真的测到了那条规则。
5. **没有需求文件时挑漏仍然会跳过**，只是改成了大声提示并写进 `gaps.md`，没有改成直接失败（旧用法很多不带需求文件）。
6. **验收角色改文件的检查有一个口子**：环境准备步骤已经改动过的文件，验收角色再改不会被发现。
7. **一条不稳定的测试**：第四轮合并后全量测试第一次 598/599，重跑 599/599，没有定位是哪一条。
8. **挑漏的抽查模式**默认会抽到内部单元测试，不公平，没修。
9. 审查报告里没排进第五轮的条目：导入扫描的几种漏判（正则字面量、带点的文件名、字符串里的 import）、
   非 ASCII 路径被 git 加引号、基线漂移与续跑的 base、以及若干低优先级项。报告在 work 目录下的
   `bastion-v1.1-审查-20261119.md`，条目编号见交接说明。
10. 另一个项目试用 v1.0 时记下的问题里，`--version` 已修；"上锁前检查失败原因"、
    "Windows 工作区里的目录联接会被删到真实目录"、心跳超时、按模型限并发这几条没做。
11. `dist/` 在开发分支上取消了跟踪，发版前要加回。
12. 默认档 = 村庄，是施工会话自己定的，开关表经过确认，默认档没有单独确认。
